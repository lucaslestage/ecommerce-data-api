# E-commerce Data Analysis & REST API

Python project combining **data analysis, relational database management and REST API development** around a social-commerce platform.

The project processes transactional e-commerce data, structures it into a relational SQLite database and exposes it through a Flask REST API. It also implements analytical queries related to sales, customers, products and content performance, as well as authentication and automated testing.

---

## Overview

The project simulates the data and backend layers of a social-commerce platform.

The relational model connects several business entities:

- users
- creators
- videos
- products
- customers
- orders
- advertising spend
- order lines

Beyond storing the data, the application extracts useful business information such as sales volumes, customer spending, product stock levels, creator performance and video-generated revenue.

---

## Main Features

### Data Processing

A raw transactional dataset is transformed into separate entity datasets before being loaded into SQLite.

The processing pipeline generates structured data for:

- creators
- videos
- products
- customers
- orders
- advertising spend
- users
- order contents

The transformation is handled by:

```bash
python data/process_data.py
```

---

### Data Analysis

SQL queries and Python functions are used to produce business-oriented indicators including:

- quantity sold by product
- low-stock products
- customer purchase history
- total customer spending
- order totals
- number of orders generated by a video
- creators generating no sales
- creator and video performance
- video net revenue
- best-performing videos

This part of the project focuses on converting transactional data into information that can support analysis and decision-making.

### Relational Database

The project uses **SQLite** and a relational data model.

Database operations are separated by business domain:

```text
db/
├── creators.py
├── customers.py
├── orders.py
├── products.py
├── users.py
└── videos.py
```

The database layer includes:

- parameterized SQL queries
- inserts and updates
- joins
- aggregations
- stock management
- relational constraints
- transaction handling

---

### REST API

A REST API is implemented with **Flask**.

Routes are separated by resource:

```text
routes/
├── auth.py
├── creators.py
├── data.py
├── orders.py
├── products.py
└── users.py
```

The API exposes operations related to users, creators, videos, products, customers and orders.

Example authenticated request:

```http
GET /users/tester
Authorization: Bearer <token>
```

## Authentication & Security

### Password Hashing

Passwords are not stored in plain text.

They are hashed using **bcrypt** before being stored in the database.

```text
Plain password
      │
      ▼
    bcrypt
      │
      ▼
Password hash
      │
      ▼
   Database
```

### JWT Authentication

After successful login, the API generates a **JSON Web Token (JWT)**.

The token:

- identifies the authenticated user
- is cryptographically signed
- expires after one hour

Protected routes require an HTTP authorization header:

```http
Authorization: Bearer <token>
```

This avoids transmitting the user's password again for every authenticated request.

## Architecture

The application follows a layered architecture:

```text
HTTP Request
     │
     ▼
Flask Routes
     │
     ▼
Database Layer
     │
     ▼
SQLite Database
```

The data preparation pipeline is handled separately:

```text
Raw Data
   │
   ▼
process_data.py
   │
   ▼
Entity CSV Files
   │
   ▼
Database Initialization
   │
   ▼
SQLite Database
```

This separation keeps data preparation, API routing and persistence logic independent.

## Setup

Clone the repository:

```bash
git clone https://github.com/lucaslestage/ecommerce-data-api.git
cd ecommerce-data-api
```

Create a virtual environment:

```bash
python -m venv .venv
```

Activate it.

Linux / macOS:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Install the dependencies:

```bash
pip install -r requirements.txt
```

---

## Environment Configuration

The JWT secret key is not stored in the repository.

Create a local `.env` file based on `.env.example`:

```text
SECRET_KEY=your-secret-key
```

The `.env` file is excluded from Git and should never be committed.

---

## Dataset

The raw dataset used for the academic project is **not redistributed in this repository**.

Raw data and generated datasets are intentionally excluded from version control:

```text
data/raw/*.csv
data/*.csv
data/*.db
```

The repository therefore contains the processing and analysis code, but not the original dataset.

If the appropriate source data is available locally, it must be placed in:

```text
data/raw/
```

The entity datasets can then be regenerated using:

```bash
python data/process_data.py
```

---

## Build the Database

First generate the entity datasets from the raw data:

```bash
python data/process_data.py
```

Then create and populate the SQLite database:

```bash
python create_db.py
```

This generates:

```text
data/tiktok.db
```

The database file is generated locally and is not committed to Git.

## Testing

The project includes an automated test suite based on **Pytest**.

Run the complete suite:

```bash
python run_tests.py
```

The custom test runner groups tests by question / implementation stage and displays one of three states:

- ✅ implementation passed
- ❌ implementation ran but produced an incorrect result
- ⏳ functionality is not implemented yet

Specific parts of the suite can also be executed:

```bash
python run_tests.py 13
```

Run several groups:

```bash
python run_tests.py 13 19 20
```

Run only unfinished or failing tests:

```bash
python run_tests.py --failed
```

Display complete tracebacks:

```bash
python run_tests.py --traceback
```

Individual Pytest tests can also be run directly:

```bash
python -m pytest tests/public -vv
```
